# Guide rapide pour les agents IA

- **Projet** : portfolio de Fiona Talbi en français, React 19, TanStack Start, Vite et TypeScript. Le dépôt est lié à Lovable : ne réécrivez pas l'historique publié de `main`.
- **Structure** : `src/data/portfolio.ts` centralise le contenu et les métadonnées. `src/components/portfolio.tsx` assemble les sections de `src/components/portfolio/` ; `src/styles.css` gère l'apparence. Les hooks `use-portfolio-navigation` et `use-reveal` gèrent la navigation et les animations. Les routes sont dans `src/routes/` ; ne modifiez pas `src/routeTree.gen.ts` à la main. Tailwind ne scanne pas `src/components/ui` (`@source not` dans `styles.css`, composants shadcn inutilisés) : si vous en importez un, retirez cette exclusion.
- **Modifier le contenu** : éditez les objets typés de `src/data/portfolio.ts`, conservez leurs identifiants stables et utilisez des métriques `{ id, value, label }`. Gardez les faits séparés des composants ; n’inventez pas de dates, diplômes, disponibilité, photo ou CV. Présentez les recommandations normalement, sans message d’attente. Leurs cartes et leur lien de menu sont visibles ; `documentPath` ouvre le PDF dans un nouvel onglet, `null` propose une demande par e-mail. Typographie française imposée par `src/test/french-typography.test.ts` : U+202F avant % ? ! ;, U+00A0 avant : et dans « 3+ ans », « 1 mois », « 910 / 990 », apostrophe ’.
- **Hero et projets** : chaque chiffre clé (`impactStats`) est un lien vers `#<targetId>` (l'`id` d'un projet ou `parcours`, vérifié par un test) ; les `id` des projets servent d'ancres, ne les renommez pas. Le portrait du hero est une illustration provisoire : pour le remplacer, écrasez `public/images/portrait-fiona.jpg` et `.avif` (1200×1500, format 4:5) ainsi que les variantes `-600` et `-900` (`.jpg` et `.avif`), par exemple avec `ffmpeg -i photo.jpg -vf scale=900:-2 portrait-fiona-900.avif`. `profile.portrait: null` n'affiche aucun visuel. Les textes réécrits sont listés dans `docs/textes-a-valider.md`. Les cartes projet de l'accueil sont des liens vers `/projets/<id>` (`src/routes/projets.$projectId.tsx`, page pré-rendue pour Pages via la liste `pages` de `vite.config.ts`) ; leur couverture est la 1re image de `project.gallery` (repli : logo sur aplat bleu bébé). Les liens du header passent par `HomeLink` (`home-link.tsx`, href absolu `BASE_URL#section`) pour fonctionner depuis toutes les pages. Les tests qui rendent des liens de routeur utilisent `src/test/render-with-router.tsx`. Page projet (`src/components/project-page.tsx`, styles dans `src/styles/project-page.css`) : retour « Tous les projets », résultats en cartes, couverture, cartes Le contexte / Ma mission (`mission`) / Ce que j'ai fait (`details`), récit optionnel (`story`), galerie (`gallery`, photos en `<picture>` AVIF + JPEG 800/1600 via `project-picture.tsx`) avec agrandissement dans un `<dialog>` natif (`project-gallery.tsx` : vrais liens vers les JPEG sans JavaScript, flèches du clavier, balayage, Échap, retour du focus), projets voisins et contact. Accueil et pages projet partagent `src/components/site-shell.tsx` (en-tête, pied de page, calque vidéo) : y ajouter ce qui doit apparaître sur toutes les pages. Balises de partage par page : `buildProjectHead` de `src/lib/seo.ts` (canonical `…/projets/<id>/`, og:image = couverture). Tests : `src/test/project-page.test.tsx`.
- **Sections et navigation** : une seule page, `#accueil` → `#projets` → `#parcours` (avec `#formation`) → `#competences` (avec `#certifications` et `#langues`) → `#recommandations` → `#contact`. Le menu (`navigation`) compte 4 liens + le bouton Contact : en ligne dès 768 px (`@media (max-width: 767px)` de `styles.css` et `INLINE_NAV_QUERY` de `site-header.tsx`, à changer ensemble), burger à un niveau en dessous. Parcours, Compétences, Recommandations et Contact sont en cartes (`sections.tsx`, `contact-section.tsx`) : Parcours = phrase d'introduction, puis Expériences (cartes avec tuile du logo de l'entreprise) | Formation (`#formation`, cartes avec tuile d'icône) et centres d'intérêt en pilules ; Compétences = 3 cartes de savoir-faire, « Boîte à outils » (tuiles logo + nom, pilules sur mobile) | Langues (`#langues`), puis Certifications (`#certifications`, une carte chacune, logo de l'organisme ou tuile d'icône) ; Recommandations = cartes-documents (feuille décorative, bouton pilule) ; Contact = grande carte bordeaux texte | actions. Leurs styles sont regroupés dans le bloc « Cartes d'information » de `styles.css` (avec leurs propres `@media`). `experience.period` s'affiche (pilule) dès qu'il est renseigné. Les icônes Lucide des savoir-faire, centres d'intérêt et outils sans logo sont choisies dans `sections.tsx` d'après les `id` des données : un nouvel `id` reçoit une icône générique.
- **Fichiers provisoires** : `public/documents/cv-fiona-talbi.pdf` (généré uniquement depuis `portfolio.ts` par `bun scripts/share-assets/cv.mjs`, à relancer après un changement de texte ; `profile.cvPath`) et `public/documents/recommandation-01.pdf` / `-02.pdf` (contenu neutre « Document provisoire »). Pour les remplacer, écrasez les fichiers sous le même nom (PDF < 1 Mo, accord des recommandants) ; `cvPath: null` retire le bouton du CV et la phrase qui l'annonce (`contact.descriptionWithoutCv`).
- **Vidéo de présentation** : décrite par `introVideo` dans `src/data/portfolio.ts` (textes dans `sectionContent.introVideo` ; `null` n'affiche rien), composants dans `src/components/portfolio/intro-video.tsx`, logique dans `src/hooks/use-intro-video.ts`. Le hero a un vrai lien vers le MP4 (« ▶ Ma présentation », rond seul sous 1000 px) qui ouvre un `<dialog>` natif ; à partir de 721 px de large (et 521 px de haut), un bandeau « Regarder · Plus tard » se pose sur le portrait ; la pastille fixe (▶ / ✕) apparaît après « Plus tard » ou quand on quitte le hero, et se masque au-dessus du pied de page et sous le menu mobile. La `<video>` n'est créée qu'au premier clic, rien de flottant n'est pré-rendu, jamais d'autoplay. Mémoire du visiteur : `localStorage['ft-intro-video:<id>']` = `later` ou `dismissed` (fin de lecture ou ✕). **Remplacer le clip de test** : écraser `public/video/presentation.mp4` (720×1280 H.264, `-movflags +faststart`, ≈ 8 Mo max), `presentation-poster.jpg` (720×1280) et `presentation-poster.webp` (360×640, vignette de la pastille) ; puis dans `introVideo` passer `isPlaceholder: false`, changer `id` (pour la reproposer à tous), mettre `title` et `durationSeconds` mesurée (`ffprobe -v error -show_entries format=duration -of csv=p=0 presentation.mp4`) ; ajouter les sous-titres `public/video/presentation.vtt` (commençant par `WEBVTT`) et `captions: "video/presentation.vtt"`. `src/test/intro-video.test.tsx` vérifie les fichiers ; tester sur iPhone depuis l'URL Pages (le Chromium de Playwright ne lit pas le H.264 : il affiche le message d'erreur du lecteur).
- **Développement** : Node.js 24 et Bun 1.4.3. `bun install --frozen-lockfile`, puis `bun run dev`. Avant livraison : `bun run test`, `bun run lint`, `./node_modules/.bin/tsc --noEmit`, `bun run build` et `GITHUB_PAGES=true bun run build`. Le lint conserve quelques avertissements React Refresh dans les composants UI.
- **Design** : direction « Maison moderne » (beige, encre, bordeaux, bleu bébé, cerise ; aucune autre teinte, seulement des mélanges `color-mix` de ces tokens), tokens dans `:root` de `src/styles.css` (aucune couleur `oklch()` en dur ailleurs) : surfaces en cartes (`--surface`, `--border-soft`, `--radius-card`, `--shadow-1/2/3`), pilules (`--radius-pill`, `.chip`, boutons `.action`), cartes interactives qui se soulèvent au survol (`--lift`) et se compriment à la pression (`--press-scale-card`) ; les cartes d'information (expériences, formation, compétences, certifications, lettres) ne bougent pas, seuls leurs boutons réagissent. Briques communes : `.block-title` (intitulé d'un groupe de cartes), `.icon-tile` (icône Lucide bordeaux sur bleu bébé), `.logo-tile` (logo sur aplat beige), `.chip-lg`. Le pied de page (commun à toutes les pages via `site-shell.tsx`) garde une marge basse de 56 px + 2 × 16 px pour que le bouton flottant « Voir la vidéo » ne recouvre jamais un lien : à ajuster si ce bouton change de taille. Fraunces seulement pour le nom du hero ; H2/H3, chiffres clés et texte en Instrument Sans (`--weight-heading`, `--tracking-heading`). Polices locales préchargées, contenu lisible sans JavaScript et animations compatibles avec `prefers-reduced-motion`. Préservez « Contact » et la barre de progression du défilement sur mobile et tablette, les cibles de 44 px minimum et les résultats avant la photo. Réservez les flèches diagonales aux vrais liens externes. Préservez les ancres, les contrastes et les interactions au clavier.
- **Logos** : SVG monochromes (encre intégrée) dans `public/logos/`, décrits dans `src/data/portfolio.ts` (`brands`, `tools[].logo`, `certifications[].logo` : `{ src, width, height, scale? }`, `width`/`height` = viewBox, `scale` = correction optique), affichés par `src/components/portfolio/logo.tsx` (hero, cartes projet, cartes d'expérience, outils, certifications Google). Logitech et outils : Simple Icons (CC0). CosmétiCar et Massilia E-consulting : mots-symboles provisoires (nom en Instrument Sans converti en tracés) ; pour mettre le logo officiel, écraser le fichier SVG (monochrome de préférence) et reporter sa viewBox dans `brands`.
- **Audit UI/UX** : `docs/audit-ui-ux.md` résume l’audit d’octobre 2026 (constats, direction artistique, vidéo, plan par lots) ; le détail technique vérifié est dans `docs/audit/annexe-constats-verifies.md`.
- **Partage & SEO** : `src/routes/index.tsx` porte toutes les balises de la page (titre, description, Open Graph, Twitter, canonical, JSON-LD `Person`), construites par les fonctions pures de `src/lib/seo.ts` à partir de `seo`, `profile` et `education` (testées dans `src/test/seo.test.ts`) ; `__root.tsx` ne garde que l'encodage, le viewport, `theme-color`, `color-scheme`, les icônes, la feuille de style et les préchargements de polices. URL absolues dérivées de `seo.siteUrl`, description de 160 caractères au plus, pas d'e-mail ni de photo dans le JSON-LD. L'image de partage est versionnée (`og-image-v1.jpg`) : en créer une nouvelle plutôt que d'écraser l'ancienne. Écrans 404 et d'erreur en français (`errorContent`, `src/components/error-screen.tsx`) ; `public/404.html` est la 404 statique de GitHub Pages, avec des liens absolus vers `/fiona-talbi-portfolio/`. `src/test/a11y.test.tsx` exige 0 violation axe (contraste vérifié dans un vrai navigateur).
- **Fichiers provisoires** : portrait, lettres de recommandation, CV, vidéo et image de partage ont des fichiers provisoires affichés comme les vrais. Leur liste et la marche à suivre pour les remplacer sont dans la section « Remplacer les fichiers provisoires » du `README.md`.
- **Publication** : `.github/workflows/pages.yml` publie automatiquement chaque push sur `main` sur GitHub Pages : <https://fio-tlb.github.io/fiona-talbi-portfolio/>. Le build Pages précompile la page `/` et chaque page `/projets/<id>/` dans `dist/client` avec le préfixe `/fiona-talbi-portfolio/`.
- **Contraintes Pages** : utilisez `import.meta.env.BASE_URL` pour les fichiers de `public/`. Pages ne fournit pas de serveur applicatif : les fonctionnalités doivent fonctionner dans le navigateur ou être précompilées.
